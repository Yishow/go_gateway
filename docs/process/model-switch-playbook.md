# Model Switch Playbook

> 目的：用最短口令切換執行模式，避免反覆確認與溝通成本。

## 1) 口令總表

### `切換模型`
- 直接啟動模型切換工作流，不再額外確認。
- **長任務**：使用 Terminal Copilot `/fleet`。
- **前端任務（UI/UX + 前端實作）**：交由 Gemini 承接。

### `強制前端`
- 在混合任務中，UI/UX 子任務優先交由 Gemini。
- 其餘非前端子任務維持既定工作流。

### `只要結果`
- 任務期間預設不打擾。
- 僅在「關鍵異常」時通報。
- 完成後一次性回報完整結果。

### `一般節奏`
- 恢復一般進度回報頻率。
- 依標準節奏回報（不進入靜默模式）。

---

## 2) 固定回報格式（啟動切換後一律使用）

```text
啟動：<已啟動的模型/流程、session資訊>
進度：<已完成 / 目前進行中>
風險：<阻塞點、超時、依賴問題；若無寫「無」>
完成：<產出、測試結果、檔案路徑、下一步>
```

---

## 3) 關鍵異常定義（`只要結果` 模式仍需通報）

- 任務中斷或進程退出（非預期）
- 連續無輸出超過約 10 分鐘
- 權限、憑證、依賴缺失導致無法前進
- 風險可能影響資料正確性或 API 契約

---

## 4) 執行原則

1. 優先遵守「不破壞 API 契約」。
2. 先測試再交付，回報可驗證結果。
3. 使用者口令優先於預設節奏。
4. 若口令衝突，依最後一個口令為準。
