## 入口與使用方式

- `/studio/v2`：沒有其他明確意圖時，開啟記錄總覽。
- `/studio/v2?view=recordings`：明確開啟總覽。
- `/studio/v2?view=recording&intent=new`：新增記錄。
- 已保存記錄由總覽開啟，使用原 canonical locator 重新讀取設定；保存新記錄後替換為新記錄網址。
- `/studio/v2?view=advanced`：保留原進階工作台。原 locator、runtime focus、合法 step/target/section/modal 意圖優先，無效或混用意圖不降級為可操作設定。
- 更新程式後必須重新建置前端及 Go 內嵌靜態檔；只有更新 Git 檔案不等於已更新正在執行的頁面。

## 本批完成的操作

1. 總覽直接新增／修改，來源、逐點算法與間隔、目的地在同頁完成，不必先展開進階區。
2. 沿原設備與點位保存流程選取來源；取消記錄草稿不回滾已明確保存的來源。
3. 草稿保留／捨棄、保存回覆晚到、同一來源往返、保存後精確讀回，沿用原權威與確認機制。
4. 保存、檢查結構、明確確認結構、明確開始分開執行；開始回覆不冒充資料庫已寫入。
5. 修改、停止、重新檢查後恢復，保留原記錄及歷史資料。簡易頁的停止先確認已保存記錄名稱及影響，取消／Escape 不送命令；確認時仍重新查證可用性。失敗操作顯示失敗，不自動重送。原進階頁既有停止方式不變。
6. 支援的逐點記錄可複製為新草稿。新記錄識別由原建立流程產生，不複製舊基準、版本、已套用或確認證據；不自動保存或開始。
7. 移除沿原確認及 tombstone 管理，不刪除已寫入歷史。已移除項目回到原進階管理入口，不復活已刪除的編輯器。
8. 同引擎 SQLite／PostgreSQL、受管一般儲存的 mixed→mixed 格式／目的地前向變更，沿原 review、reserve、schema、readiness、future cutover 與 ledger。

前向變更保留 RecordID、lineage、完整來源與逐點算法／週期。跨引擎、legacy↔mixed、不可表示的缺值或精確值政策不偷偷轉換。`skip_row` 或 `exact_source` 無法表示為目標寬表時，保留明確拒絕。

長表可能使用受管共用資料表，以記錄識別隔離，不把「複製記錄」說成一定新增實體表。變更目的地時由伺服器依新連線推導受管長表名稱，不沿用舊目的地的推導名稱。

## 資料語意

- 不同點位使用自己的計算方式、對齊週期與窗口。
- 寬表未到期項目為 NULL／not_due；長表僅產生符合原政策的到期項目。
- 首次 counter 讀值建立基準，不把累積原值或任意 0 當差值。
- 新 generation 使用新範圍的 counter proof 與基準，不複製前代 baseline。
- 切換後仍可排空屬於舊時間區間的工作；不得讓兩代擁有同一個新的時間區間。歷史列及收據保持不變。

### 保留的失敗與限制

- 原型 v9 是方向參照，不當成真實設備／資料庫成功證據。

- 一次 QA 選單操作失誤產生未 Apply 的錯誤 reservation；保留原 trace／資料庫後，以完整測試備份重置。沒有把此操作寫成產品取消成功，也沒有為它新增取消 API。
- schema／scope 變更後曾有舊版本 metadata 409，後續以目前版本讀取成功；輸入過程的無效地址 400 及既有表單標籤提醒保留，不聲稱全程 console 零訊息。
