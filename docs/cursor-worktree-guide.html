什麼是 Git Worktree？

Git Worktree 允許你在同一個 Git 倉庫中，同時檢出多個分支到不同的目錄。 每個 worktree 都有自己獨立的工作目錄和暫存區，但共享同一個 .git 資料庫。

💡

為什麼在 Cursor 中使用 Worktree？

Cursor 2.0+ 使用 worktree 來支援多代理並行開發。每個 AI 代理在獨立的 worktree 中工作，避免檔案衝突，讓你可以同時執行多個任務。

環境設置

⚙️

Step 1: 確認 Cursor 版本

首先確認你的 Cursor 版本是 2.0 或更高版本：

Cursor IDE - 檢查版本

Help → About Cursor

⚡
Cursor
Version 2.3.x
📁

Step 2: 規劃 Worktree 目錄結構

建議的目錄結構：

目錄結構
# 主專案位置 C:\AIProject\go_gateway\ # ← 主專案（包含 .git 目錄） # Worktree 存放位置（建議） C:\Users\{用戶名}\.cursor\worktrees\ └── go_gateway\ ├── scanner\ # ← Worktree 1 ├── monitor\ # ← Worktree 2 ├── bugfix\ # ← Worktree 3 └── auth\ # ← Worktree 4
✅

為什麼使用這個結構？

  • Worktree 與主專案分離，避免混淆
  • 統一的存放位置，方便管理
  • Cursor 專用目錄，不影響其他工具
🔧

Step 3: 創建 Worktree

PowerShell / Terminal
# 1. 進入主專案目錄 cd C:\AIProject\go_gateway # 2. 確保 main 分支是最新的 git checkout main git pull origin main # 3. 創建 worktree（同時創建新分支） git worktree add ~/.cursor/worktrees/go_gateway/scanner -b feature/device-scanner # 4. 查看所有 worktree git worktree list
❌

避免使用 Detached HEAD！

錯誤示範：git worktree add <path>（沒有指定分支）

這會導致 commit 可能丟失，且 Cursor 可能無法正確識別 Git 狀態。

合併與清理

PowerShell / Terminal
# 1. Push 分支到遠端 git push -u origin feature/device-scanner # 2. 創建 Pull Request（使用 GitHub CLI） gh pr create --title "feat: 新增設備掃描功能" --body "## 變更內容\n- 新增掃描組件" # 3. 合併後，回到主專案目錄 cd C:\AIProject\go_gateway # 4. 移除 worktree git worktree remove ~/.cursor/worktrees/go_gateway/scanner # 5. 清理無效的 worktree 引用 git worktree prune # 6. 刪除本地分支（可選） git branch -d feature/device-scanner
⚠️

重要：先關閉 Cursor 視窗，再移除 Worktree

如果 Cursor 還在使用該目錄，可能會導致檔案鎖定錯誤。

多代理模式（Multi-Agent）

🤖

Cursor 2.0+ 多代理功能

Cursor 2.0 引入了多代理功能，允許最多 8 個 AI 代理同時工作。 每個代理在獨立的 worktree 中運行，避免檔案衝突。

🤖 多代理並行工作示意圖
🤖
Agent 1
前端開發
worktree/frontend
🤖
Agent 2
後端 API
worktree/backend
🤖
Agent 3
測試撰寫
worktree/tests
🤖
Agent 4
文檔更新
worktree/docs
✅

多代理優點

  • 並行處理多個任務
  • 每個代理專注單一職責
  • 自動隔離避免衝突
  • 可比較不同方案
⚠️

注意事項

  • 沙盒模式可能需要頻繁確認權限
  • 代理可能「脫離」worktree
  • 需要仔細審查合併結果
⚙️

設定多代理模式

1

開啟代理面板

在 Cursor 側邊欄找到 Agents 標籤

2

創建代理群組

點擊 + 創建新的多代理任務，輸入任務描述

3

選擇代理數量

選擇 2-8 個代理，可為每個代理指定角色（如：效能優化、安全性）

4

啟動並監控

Cursor 會自動為每個代理創建 worktree，完成後可比較結果

💡

關閉沙盒模式（如需要）

如果頻繁的權限確認很煩人，可以在設定中：

Agent → Auto-Run Mode → Run Everything（注意：這會降低安全性）

命令速查表

命令 說明 範例
git worktree add <path> -b <branch> 創建新分支的 worktree git worktree add ~/wt/scanner -b feature/scanner
git worktree add <path> <branch> 使用現有分支創建 worktree git worktree add ~/wt/hotfix hotfix/bug
git worktree list 列出所有 worktree -
git worktree remove <path> 移除 worktree git worktree remove ~/wt/scanner
git worktree remove <path> --force 強制移除 worktree git worktree remove ~/wt/scanner --force
git worktree prune 清理無效的 worktree 引用 -
cursor <path> 在 Cursor 中開啟資料夾 cursor ~/wt/scanner

最佳實踐

✅ 應該做的事

  • 使用有意義的分支名稱
  • 每個 worktree 專注一個功能
  • 定期從 main 同步更新
  • 小步提交，清楚的 commit message
  • 先關閉 Cursor 再刪除 worktree
  • 使用 PR 進行代碼審查
  • 定期清理已合併的 worktree

❌ 不應該做的事

  • 使用 detached HEAD 模式
  • 在主專案直接編輯 worktree 檔案
  • 同時 checkout 同一個分支
  • 忘記 push 就刪除 worktree
  • 長時間不同步 main
  • 在 worktree 中執行 git init
  • 刪除 .git 指標檔案

常見問題 FAQ

Q: Cursor 顯示「No Git repository」怎麼辦？

這是 Cursor 2.x 的已知問題。當 worktree 的 .git 是指標檔案而非目錄時，可能無法識別。

解決方案：

  • 使用終端機執行 Git 命令
  • 等待 Cursor 更新修復此問題
  • 嘗試重新開啟資料夾
Q: 如何解決 detached HEAD 狀態？
# 在 worktree 目錄中 cd ~/.cursor/worktrees/go_gateway/scanner # 創建並切換到新分支 git checkout -b feature/device-scanner # 或切換到現有分支 git checkout feature/device-scanner
Q: 移除 worktree 時出現錯誤怎麼辦？
  1. 確保已關閉所有使用該目錄的 Cursor 視窗
  2. 使用 --force 強制移除
  3. 執行 git worktree prune 清理
Q: 如何在 worktree 之間共享 node_modules？

推薦方案：使用 pnpm

pnpm 使用全局 store，自動共享依賴，節省磁碟空間。

# 安裝 pnpm npm install -g pnpm # 在每個 worktree 中使用 pnpm pnpm install
Q: 多代理模式下如何避免權限確認彈窗？

在 Cursor 設定中：

Settings → Agent → Auto-Run Mode → Run Everything

⚠️

注意：這會降低安全性，代理可以直接修改檔案而不需要確認。
