📋 概述

本函式庫提供完整的 Fatek PLC Binary Communication Protocol 實現，支援以下特性：

  • Binary Protocol (雙速率二進制碼)：比 ASCII 快 2 倍的傳輸速率
  • 自動分包機制：超過點數限制自動分割多個請求
  • CRC-16 Modbus 校驗：確保資料傳輸正確性
  • 完整的例外處理：分類的錯誤類別，詳細的錯誤信息
  • 詳細的日誌記錄：所有通訊過程均被記錄
  • 生產環境優化：請求批合併、狀態管理、執行緒安全

📦 Binary Protocol 訊息格式

查詢訊息結構 (Query)

┌─────────────────────────────────────────────────────────────┐ │ Header │ ID │ Length (2B) │ Payload │ CRC-16 (2B) │ Terminator │ │ 0x51 │ 0x10│ (LE) │ (*) │ (LE) │ 0x55AA │ └─────────────────────────────────────────────────────────────┘ 1 byte 1 byte 2 bytes n bytes 2 bytes 2 bytes

響應訊息結構 (Response)

┌─────────────────────────────────────────────────────────────┐ │ Header │ ID │ Length (2B) │ Payload │ CRC-16 (2B) │ Terminator │ │ 0x52 │ 0x10│ (LE) │ (*) │ (LE) │ 0x55AA │ └─────────────────────────────────────────────────────────────┘ 1 byte 1 byte 2 bytes n bytes 2 bytes 2 bytes

Payload 結構

查詢 Payload: ┌──────────────┬──────────────┬─────────────────────┐ │ Station ID │ Command Code │ 命令特定資料 │ │ (1 byte) │ (1 byte) │ (n bytes) │ └──────────────┴──────────────┴─────────────────────┘ 響應 Payload: ┌──────────────┬──────────────┬─────────────┬─────────────────┐ │ Station ID │ Command Code │ Error Code │ 響應資料 │ │ (1 byte) │ (1 byte) │ (1 byte) │ (n bytes) │ └──────────────┴──────────────┴─────────────┴─────────────────┘
Header (頭字節)
• 0x51 = 查詢訊息
• 0x52 = 響應訊息
ID
• Binary Protocol 的預設值為 0x10
• 用於區分不同的通訊協議類型
Length
• Payload 的字節數
• Little-endian 格式（低字節在前）
• CRC 和終止符不計入長度
CRC-16
• Modbus CRC-16 演算法
• 計算範圍：Length + Payload
• Little-endian 格式
• 多項式：0xA001，初值：0xFFFF
Terminator
• 預設值：0x55AA
• 表示訊息結束

⚙️ 命令代碼 (Command Code)

代碼 16進制 說明 讀取數量限制 寫入數量限制
READ_DISCRETE 0x44 讀取離散點 (Y/M/S/T/C/X) 1~256 -
WRITE_DISCRETE 0x45 寫入離散點 - 1~256
READ_REGISTER 0x46 讀取連續暫存器 (R/D/W) 1~64 -
WRITE_REGISTER 0x47 寫入連續暫存器 - 1~64
MIXED_READ 0x48 混合讀取 (離散+暫存器) 1~64 點或字 -
MIXED_WRITE 0x49 混合寫入 (離散+暫存器) - 1~32 點或字
LOOPBACK_TEST 0x4E 迴路測試 0~256 bytes 0~256 bytes
READ_SYSTEM_STATUS 0x53 讀取系統狀態 - -

💡 自動分包說明

當讀取/寫入數量超過限制時，函式庫會自動分割成多個請求：

  • READ_DISCRETE：每包最多 256 個點
  • READ_REGISTER：每包最多 64 個暫存器 (32 個 32-bit)
  • 自動合併響應資料，用戶無需關注分包細節

🚨 例外類別 (Exception Classes)

函式庫定義了完整的例外階層，用於區分不同類型的錯誤：

例外階層

FatekException ├─ FatekConnectionError # 連線錯誤（序列埠無法開啟） ├─ FatekCommunicationError # 通訊錯誤（PLC 回覆錯誤碼） ├─ FatekProtocolError # 協議錯誤（訊息格式不符） ├─ FatekTimeoutError # 逾時錯誤（未在時限內收到響應） ├─ FatekDataError # 資料錯誤（數據超過限制） └─ FatekAddressError # 位址錯誤（位址無效）

例外使用範例

FatekConnectionError

FatekConnectionError: 無法連線到序列埠

原因：序列埠不存在或已被占用

解決：檢查序列埠號、驅動程式、或其他應用程式的占用

FatekTimeoutError

FatekTimeoutError: 接收訊息逾時

原因：在指定時間內未收到 PLC 響應

解決：檢查通訊線路、PLC 電源、波特率設置

FatekProtocolError

FatekProtocolError: CRC 驗證失敗

原因：接收到的資料 CRC 校驗錯誤

解決：檢查通訊線路品質、嘗試降低波特率

FatekDataError

FatekDataError: 讀取數量超過限制

原因：請求的讀取/寫入數量超過協議限制

解決：函式庫已自動分包，通常不會遇到此錯誤

FatekCommunicationError

FatekCommunicationError: PLC 錯誤: 非法位址

原因：PLC 回覆了錯誤代碼（如 0x04 非法位址）

解決：檢查讀取/寫入的位址是否有效

💻 Python 使用範例

基本連線範例

from fatek_plc_library import ( FatekPLC, SerialConfig, PLCModel, ComponentType ) # 建立序列埠配置 config = SerialConfig( port="COM1", # Windows # port="/dev/ttyUSB0", # Linux # port="/dev/tty.usbserial", # macOS baudrate=9600, # Fatek 預設 bytesize=8, parity='E', # Even Parity stopbits=1, timeout=1.0 # 1 秒逾時 ) # 建立 PLC 實例 plc = FatekPLC( config=config, station_id=1, # Slave Station Number plc_model=PLCModel.FB_SERIES ) # 連線 plc.connect() print("已連線到 PLC") # 執行操作... # 斷線 plc.disconnect() print("已斷線")

讀寫操作範例

# ===== 讀取操作 ===== # 讀取輸出點 Y0~Y9 (10 個點) y_values = plc.read_discrete( component_type=ComponentType.Y, start_address=0, quantity=10 ) print(f"Y0~Y9: {y_values}") # 輸出: Y0~Y9: [1, 0, 1, 1, 0, 0, 1, 0, 1, 1] # 讀取暫存器 R0~R9 (10 個 16-bit 暫存器) r_values = plc.read_register( component_type=ComponentType.R, start_address=0, quantity=10, is_32bit=False ) print(f"R0~R9: {r_values}") # 輸出: R0~R9: [1000, 2000, 3000, ...] # 讀取 32-bit 暫存器 D0~D4 d_values = plc.read_register( component_type=ComponentType.D, start_address=0, quantity=5, is_32bit=True ) print(f"D0~D4: {d_values}") # ===== 寫入操作 ===== # 寫入輸出點 Y0~Y3 plc.write_discrete( component_type=ComponentType.Y, start_address=0, values=[1, 0, 1, 0] ) print("已寫入 Y0~Y3") # 寫入暫存器 R0=1000, R1=2000, R2=3000 plc.write_register( component_type=ComponentType.R, start_address=0, values=[1000, 2000, 3000], is_32bit=False ) print("已寫入 R0~R2") # ===== 隨機讀取 ===== # 讀取不連續的暫存器位址 random_data = plc.read_random_registers([ (ComponentType.R, 0), (ComponentType.R, 10), (ComponentType.R, 100), (ComponentType.D, 0) ]) print(f"隨機讀取: {random_data}") # 輸出: 隨機讀取: {'R0': 1000, 'R10': 5000, 'R100': 9999, 'D0': 123456}

完整的錯誤處理範例

from fatek_plc_library import ( FatekException, FatekConnectionError, FatekTimeoutError, FatekCommunicationError, FatekProtocolError ) try: # 連線階段 try: plc.connect() except FatekConnectionError as e: print(f"❌ 連線失敗: {e}") exit(1) # 讀取階段 try: values = plc.read_discrete(ComponentType.Y, 0, 10) except FatekTimeoutError as e: print(f"⏱️ 逾時: {e} - 檢查 PLC 電源和通訊線路") except FatekProtocolError as e: print(f"📡 協議錯誤: {e} - 檢查線路品質") except FatekCommunicationError as e: print(f"🔴 PLC 錯誤: {e} - 檢查位址或數值") # 寫入階段 try: plc.write_register(ComponentType.R, 0, [1000]) except FatekCommunicationError as e: print(f"寫入失敗: {e}") except FatekException as e: # 捕獲所有 Fatek 例外 print(f"未預期的 Fatek 錯誤: {e}") finally: # 確保斷線 if plc.is_connected(): plc.disconnect() print("✅ 已正確斷線")

進階用法：自動分包和日誌

import logging from fatek_plc_library import FatekLogger # ===== 設定詳細日誌 ===== # 設定日誌 logger = FatekLogger.setup_logger("my_plc_app") logger.setLevel(logging.DEBUG) # 建立 PLC 實例並傳入日誌對象 plc = FatekPLC(config=config, logger=logger) plc.connect() # ===== 自動分包讀取 ===== # 讀取 500 個輸入點 (自動分成 2 個請求: 256 + 244) x_values = plc.read_discrete( component_type=ComponentType.X, start_address=0, quantity=500 # 超過 256 限制 ) print(f"讀取 {len(x_values)} 個輸入點") # 日誌會記錄: # 構建查詢訊息: STN=01, CMD=44, Length=8, HEX=... # 已發送: 51 10 08 00 01 44 01 00 00 00 ... (第一包) # 已接收: 52 10 ... (第一包回應) # 構建查詢訊息: STN=01, CMD=44, Length=8, HEX=... (第二包) # 已發送: ... (第二包) # 已接收: ... 🔧 序列埠配置指南

標準 Fatek PLC 設置

# Fatek PLC 預設通訊參數 config = SerialConfig( port="COM1", baudrate=9600, # 波特率 bytesize=8, # 資料位 parity='E', # Even Parity stopbits=1, # 停止位 timeout=1.0 # 逾時 (秒) )

跨平台序列埠名稱

# Windows port = "COM1" port = "COM2" port = "COM3" # USB 轉串列 # Linux port = "/dev/ttyS0" # 內置 port = "/dev/ttyUSB0" # USB 轉串列 port = "/dev/ttyACM0" # 虛擬序列埠 # macOS port = "/dev/tty.usbserial" port = "/dev/cu.usbserial"

通訊參數說明

  • Baudrate (波特率): 9600 bps 是 Fatek 預設值，某些型號可支援更高速率
  • Bytesize: 通常為 8 bits，部分設置可能為 7 bits
  • Parity:
    • E = Even (偶校驗) - 推薦
    • O = Odd (奇校驗)
    • N = None (無校驗)
  • Stopbits: 通常為 1，部分為 2
  • Timeout: 建議 1.0~2.0 秒，根據網路品質調整

🔍 波特率選擇指南

波特率 傳輸速度 適用情景
9600 ~1.2 KB/s 預設、大多數應用
19200 ~2.4 KB/s 本地 RS-485
38400 ~4.8 KB/s 短距離、優質線路
57600 ~7.2 KB/s 非常短距離

⚡ 效能優化建議

1. 批量讀寫操作

將多個分散的讀寫操作合併為連續操作，減少通訊次數：

# ❌ 不推薦：多次序列讀取 for i in range(100): value = plc.read_register(ComponentType.R, i, 1) # 100 次通訊往返 # ✅ 推薦：單次批量讀取 values = plc.read_register(ComponentType.R, 0, 100) # 自動分包為最少請求數

2. 自動分包優化

利用函式庫的自動分包機制，無需手動分割：

# ❌ 不推薦：手動分包 for start in range(0, 1000, 64): values = plc.read_register(ComponentType.R, start, 64) # 容易出錯 # ✅ 推薦：自動分包 values = plc.read_register(ComponentType.R, 0, 1000) # 自動處理分包和合併

3. 逾時設置優化

# 良好的通訊線路 config = SerialConfig(port="COM1", timeout=0.5) # 長距離或干擾環境 config = SerialConfig(port="COM1", timeout=2.0) # 大容量讀寫 (自動分包) config = SerialConfig(port="COM1", timeout=3.0)

4. 日誌級別調整

# 生產環境：INFO 級別 logger.setLevel(logging.INFO) # 調試階段：DEBUG 級別 logger.setLevel(logging.DEBUG) # 禁用日誌（最小開銷） logger.setLevel(logging.CRITICAL)

🐛 故障排除指南

問題 1：無法連線 (FatekConnectionError)

原因和解決方案

  • 序列埠號不正確
    • Windows：使用設備管理器檢查 COM 埠
    • Linux：執行 ls /dev/tty*
    • macOS：執行 ls /dev/tty.* /dev/cu.*
  • 序列埠被占用
    • 關閉其他應用程式（如串列終端、PLC 編程軟體）
  • 驅動程式缺失
    • USB 轉串列：安裝晶片組驅動 (CH340, PL2303, FT232 等)
  • 權限不足
    • Linux：sudo usermod -a -G dialout $USER

問題 2：逾時 (FatekTimeoutError)

原因和解決方案

  • PLC 未開機或無反應
    • 檢查 PLC 電源指示燈
    • 檢查通訊埠 LED 指示燈
  • 通訊線路故障
    • 檢查 RS-485 線路 A、B、GND 接線
    • 檢查線路是否斷開或短路
    • 檢查線路長度（RS-485 最長 ~1200m）
  • 波特率不匹配
    • 確認 PLC 設置的波特率與程式一致
  • 逾時設置過短
    • 增加 timeout 值：timeout=2.0

問題 3：CRC 驗證失敗 (FatekProtocolError)

原因和解決方案

  • 通訊線路品質差
    • 檢查是否有電磁干擾（馬達、變頻器、焊機等）
    • 使用屏蔽電纜
    • 加強接地
  • 波特率過高
    • 降低波特率至 9600 或 19200
  • 線路太長
    • RS-485 線路長度不超過 1200m

問題 4：位址錯誤 (FatekCommunicationError: 非法位址)

原因和解決方案

  • 位址超出範圍
    • 檢查 PLC 的最大位址（如 Y0~Y63）
    • 檢查暫存器是否存在（某些區間可能不可用）
  • 位址類型錯誤
    • Y 只能寫入，不能讀取（某些型號）
    • 確認位址元件類型是否匹配

📊 協議規格

訊息大小限制

  • 最小訊息：8 bytes (頭+ID+長度+CRC+終止符)
  • 最大訊息：預設 256 bytes payload
  • 單次操作：最多 256 個點或 64 個字

傳輸特性

  • 傳輸模式：全雙工 RS-485
  • 編碼方式：二進制（Binary）
  • 校驗方法：CRC-16 Modbus
  • 位元組序：Little-endian (CRC, Length)
  • Big-endian (位址、資料)

支援的 PLC 型號

  • FBs 系列
  • M 系列
  • 其他支援 Binary 協議的型號

📈 效能指標

通訊速率 (9600 bps)

  • 單個字讀取：~20-30 ms
  • 64 字批量讀取：~50-80 ms
  • 256 點批量讀取：~100-150 ms

吞吐量

  • 9600 bps: ~1.2 KB/s
  • 19200 bps: ~2.4 KB/s
  • 38400 bps: ~4.8 KB/s

重試機制

  • 超時重試：可手動實現
  • CRC 失敗：自動丟棄，等待重試
  • 通訊錯誤：拋出例外供上層處理
