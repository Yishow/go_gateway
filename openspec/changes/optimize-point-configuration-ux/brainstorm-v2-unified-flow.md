# 🧠 Brainstorm: 整合式流程設計 - 減少頁面、統一體驗

## Context

用戶反饋初版方案（混合模式）仍過於分散：

- **問題 1**：目前有 9 個獨立頁面（Dashboard, Devices, Points, Tags, Mappings, PollingGroups, Settings, Onboarding, MappingWizard）
- **問題 2**：設定流程需要在多個頁面間跳轉
- **問題 3**：資料點設定與標籤映射分離，認知負擔高

**目標**：減少頁面數量、更一致化的設定流程

---

## Option A: 設備中心模式（Device-Centric）

將所有配置集中到「設備詳情頁」，以設備為核心展開點位、標籤、映射。

```
Devices → Device Detail
           ├── Tab: 基本資訊
           ├── Tab: 點位配置 ★ (含批量建立、記憶體格子)
           ├── Tab: 標籤映射
           └── Tab: 收集狀態
```

**頁面結構**：

```
Dashboard (概覽)
Devices (列表 → 詳情)
    └── DeviceDetail (多 Tab 整合)
           ├── Info Tab
           ├── Points Tab (批量建立、格子視覺化)
           ├── Mappings Tab (點位 → 標籤快速映射)
           └── Monitor Tab (即時狀態)
Settings
```

✅ **Pros:**

- 頁面數量大幅減少（9 → 4）
- 以設備為中心，符合工控思維
- 點位與映射在同一頁面，無需跳轉
- 上下文清晰，操作連貫

❌ **Cons:**

- 無法跨設備管理點位/標籤
- DeviceDetail 頁面較複雜
- 需重構現有頁面

📊 **Effort:** High

---

## Option B: 流程導向模式（Flow-Oriented）

按照資料管線流程，將頁面整合為「配置流程」與「監控面板」兩大區塊。

```
┌─────────────────┐     ┌─────────────────┐
│   Configuration │ ──▶ │    Monitoring   │
│   (設定流程)     │     │   (監控面板)    │
└─────────────────┘     └─────────────────┘
         │
         ▼
   統一設定精靈
   Step 1: 設備
   Step 2: 點位 (批量)
   Step 3: 標籤
   Step 4: 映射
   Step 5: 啟動
```

**頁面結構**：

```
Dashboard (監控 + 快速入口)
ConfigWizard (統一設定精靈)
    └── Step-by-step 引導
DataExplorer (資料管理)
    └── Tab: Devices | Points | Tags | Mappings
Settings
```

✅ **Pros:**

- 新手友好，引導式體驗
- 流程清晰，一氣呵成
- 進階使用者可用 DataExplorer 快速管理

❌ **Cons:**

- 兩種模式（Wizard vs Explorer）可能造成混淆
- 精靈流程較死板
- 已有資料時難以復用精靈

📊 **Effort:** High

---

## Option C: 智慧 Dashboard 模式（Smart Dashboard）⭐

將 Dashboard 擴展為「一站式工作台」，整合快速操作與資料管理。

```
Dashboard (工作台)
├── 左側: 設備樹狀導覽
│         Device A
│          ├── Points (5)
│          └── Mappings (3)
│         Device B
│          └── ...
│
├── 中間: 動態內容區
│         (依左側選取顯示對應內容)
│         - 選設備 → 顯示設備詳情 + 點位列表
│         - 選點位 → 顯示點位詳情 + 映射設定
│
└── 右側: 快速操作面板
          ├── [+ 批量建立點位]
          ├── [+ 快速映射]
          └── [狀態監控]
```

**頁面結構**：

```
Dashboard (一站式工作台) ← 唯一主頁面
    ├── 設備樹狀導覽
    ├── 動態內容區
    └── 快速操作面板
Settings
```

✅ **Pros:**

- **極簡頁面結構（2 頁）**
- 類似 IDE 的操作體驗
- 左側導覽提供全局視野
- 右側面板快速操作
- 所有資料一目了然

❌ **Cons:**

- 頁面資訊密度高
- 小螢幕適應性挑戰
- 開發工作量較大
- 較激進的 UI 變動

📊 **Effort:** Very High

---

## Option D: 漸進式整合（Incremental Integration）⭐⭐ 推薦

在現有架構上漸進式整合，保留獨立頁面但增加「上下文連結」。

```
現有架構 + 強化連結
┌──────────────────────────────────────────────────────────────┐
│  Dashboard                                                    │
│  ┌─────────────────────────────────────────────────────────┐ │
│  │ Device: PLC-001                              [切換 ▼]   │ │
│  └─────────────────────────────────────────────────────────┘ │
│                                                               │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐            │
│  │ Points  │ │Mappings │ │ Status  │ │ Config  │            │
│  │   12    │ │    8    │ │ Active  │ │ Ready   │            │
│  └─────────┘ └─────────┘ └─────────┘ └─────────┘            │
│                                                               │
│  ┌─────────────────────────────────────────────────────────┐ │
│  │ 快速操作: [+ 批量建立點位] [+ 快速映射] [測試連線]      │ │
│  └─────────────────────────────────────────────────────────┘ │
│                                                               │
│  記憶體格子視覺化 (當前設備)                                  │
│  ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ...               │
│  │D100 │ │D101 │ │D102 │ │D103 │ │D104 │                    │
│  │ 🟢 │ │ 🟢 │ │ ⚪ │ │ ⚪ │ │ ⚪ │                    │
│  └─────┘ └─────┘ └─────┘ └─────┘ └─────┘                    │
│                                                               │
│  點選格子 → 側邊滑出面板 (Point 詳情 + 映射設定)             │
└──────────────────────────────────────────────────────────────┘
```

**核心改進**：

1. **設備上下文**：所有頁面共享「當前設備」選擇器
2. **Dashboard 強化**：整合記憶體格子視覺化
3. **側邊滑出面板**：點位/標籤/映射詳情在側邊面板操作，無需跳頁
4. **保留獨立頁面**：進階使用者可用獨立頁面深度管理

**頁面結構**：

```
Dashboard (主工作區 + 記憶體格子)
Devices (列表，快速切換設備)
Points (進階管理，保留)
Tags (全域標籤管理)
Settings
```

✅ **Pros:**

- **漸進式改造，風險低**
- 保留現有頁面結構，降低學習成本
- Dashboard 成為核心工作區
- 側邊面板避免頁面跳轉
- 設備上下文貫穿全局

❌ **Cons:**

- 頁面數量減少有限（9 → 5）
- 需要統一「當前設備」狀態管理
- Dashboard 變得較複雜

📊 **Effort:** Medium

---

## 💡 Recommendation

**Option D: 漸進式整合** 是最佳平衡點，理由如下：

| 評估維度   | A 設備中心 | B 流程導向 | C 智慧 Dashboard | D 漸進整合 |
| ---------- | ---------- | ---------- | ---------------- | ---------- |
| 頁面精簡   | ⭐⭐⭐⭐   | ⭐⭐⭐     | ⭐⭐⭐⭐⭐       | ⭐⭐⭐     |
| 流程一致   | ⭐⭐⭐⭐   | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐         | ⭐⭐⭐⭐   |
| 開發風險   | ⭐⭐       | ⭐⭐       | ⭐               | ⭐⭐⭐⭐   |
| 使用者適應 | ⭐⭐⭐     | ⭐⭐⭐     | ⭐⭐             | ⭐⭐⭐⭐⭐ |
| **總分**   | 13         | 13         | 12               | **16**     |

**如果您追求極致精簡**，可考慮 **Option A（設備中心模式）**，將一切集中到設備詳情頁。

---

## 建議的實施路徑

### 若選 Option D（漸進整合）：

**Phase 1**: Dashboard 強化

- 新增「當前設備選擇器」
- 整合記憶體格子視覺化
- 整合批量建立功能

**Phase 2**: 側邊面板系統

- 建立通用 `SidePanel` 組件
- 點位詳情面板
- 映射設定面板

**Phase 3**: 頁面精簡

- 移除獨立 MappingWizard 頁面
- 將 PollingGroups 移入 Settings
- 清理冗餘入口
