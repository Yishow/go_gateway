# Studio v2 資料庫流程設計

## Context

以 evidence.md 的固定版本來源為依據。上一輪下載包只是未合併的參考，不是 main 已有的修正。既有規格已要求真實資料與版本保護，但第 4 步規格另保留了示範動畫成功的要求，必須一起收斂。文件相互矛盾不代表舊示範行為可以恢復。

本次只交付文件。以下設計是待實作的目標，不是現況說明。

## Goals / Non-Goals

**In scope**：第 4 步資料庫準備、記錄方案與設備／測量項目／連線的關聯、設定儲存一致性、建表／試寫結果、欄位編輯與預覽保護、文案與可操作性。

**Out of scope**：新增資料庫驅動、改寫 PLC 或採集排程、重寫 Modbus Share 啟用保護、增加舊 Studio 入口、擴建全產品報表、部署及現場寫入。真實測試只使用可丟棄的測試資料庫。

## Decisions

### 1. 先停止錯誤承諾，再開放真正操作

先讓 `SchemaApply` 與 `TestWrite` 的未實作路徑回覆 HTTP 501、`success: false`、固定安全錯誤代碼與可行動說明，不帶成功資料。前端顯示「尚未開放，沒有執行」，保留使用者設定。

這只處理記錄方案的空實作，不將一般 `GenerateSchema` 一起停用。後續新增真實操作時，只有已完成該資料庫種類的整合測試才開放；未通過的種類維持不可執行。連線成功、方案存在或宣告能力都不是寫入證據。

### 2. 目標只能來自已儲存資料

瀏覽器送出已儲存的連線編號及預期版本，後端驗證工作區可用範圍並解析真正種類與憑證；不相信瀏覽器自行填的種類來選擇建表語法。記錄方案建立、預覽、建表與試寫共用同一個目標選取結果。

不再使用 `default-sqlite`、`meas-primary` 或第一台設備當補值。從已儲存的測量項目讀取每一筆設備歸屬；原始點位編號不能未經確認就當成測量項目編號。沒有合法成員時停止建立，指出缺少的設定。

多方案時必須選方案；只有唯一且符合目前範圍的方案才可自動選取。切換方案／設備／連線會清除該範圍的預覽和試寫顯示。清單讀取失敗與空清單必須分開，不能把載入失敗當成可以重新建立。

重用未改變的已存連線，不因密碼被遮蔽而要求重填。密碼原字串不得 trim；未變更、明確清除及重新提供必須能區分。身分改變後不沿用前一端點密碼。憑證、連線密碼與敏感路徑不寫入普通畫面、記錄或預覽簽章。

### 3. 真實欄位與建表建議分開

優先沿用 `dbTargetAPI.listTables(id)` 所對應的服務讀取能力，由服務層與查詢 hook 統一處理，不在畫面元件散落呼叫。查詢資料以已存連線身分版本、資料庫、分類及資料表分開；改變任何一項就使舊結果失效。

明確顯示尚未查詢、讀取中、表存在、表不存在、權限不足或查詢失敗。既有表查詢失敗時不能使用範例欄位補位。新表的欄位是待確認建議；既有配對若仍相容就保留，缺少或有歧義就標示待修復，不能循環使用欄位或以名稱相似直接確認。

欄位衝突沿用 `workspace-database-row-groups`：同一群組且有合法資料列識別方式的共用欄位可以存在；跨群組或缺少識別方式仍阻擋。不把此次 UI 整理變成資料寫入語意變更。

### 4. 一次儲存要有一致的結果

先故意使第二段本地儲存失敗，確認連線／分組及欄位對應／工作區參照的實際行為。同一個本地設定資料庫的變更使用同一筆交易與版本檢查：一起成功或一起失敗。尚未儲存完成的設定不取得可執行資格。

外部建表不假裝能與本地設定跨資料庫一起還原。改為先保存操作編號與目標版本，再記錄實際結果；結果不確定時顯示需要核對，禁止假成功和盲目重試。啟用設備前重新取得最新後端可執行結果，保留目前的工作區／設定版本與 readiness token 檢查。

### 5. 預覽與建表必須指向同一份設定

預覽確認資料由後端保存：工作區、方案與其版本、目標連線與身分版本、表名稱範圍、目前設定版本、將執行的內容、期限及操作狀態。新增欄位需遵循相容讀取與既有資料庫 migration 流程；不可只存在瀏覽器。

建表執行前，後端重讀目前資料並比較版本、所有權與有效期限；另一個分頁改動後回覆 409，不執行。未知或非所屬確認資料不執行；以不洩漏其他工作區資訊的 404 或已存在的安全拒絕格式回覆。

同一確認資料必須先被原子地取得執行權；重複或同時點擊不能再跑一遍。完成後保留可查詢的結果，回覆遺失時先查詢，不重新建表。支援完整還原的資料庫採交易；不支援時記錄已完成項目與未確定項目，不能說全部成功或全部還原。

預覽本身不得建立資料表或寫入測試列。資料表名稱／前綴受驗證，語法使用目標驅動的安全名稱處理，不直接信任傳入字串。後端操作持續中，切換畫面不代表取消成功；新的寫入動作需等待操作結果核對。

### 6. 試寫、讀回與清理各自有證據

確認後才試寫，使用後端保存的操作編號與目標範圍；在目標端以可持久辨識的測試記錄身分避免重複。對相同操作重試或服務重新啟動後，先查既有狀態；無法確認有沒有寫入就停止，不再插入一筆。

回讀比較實際測試內容，不只比較編號。沿用並收斂 `written_verified`、`written_unverified`、`failed`；另以 `unknown` 表示無法確認是否寫入。前端遇到未知狀態也不得顯示成功。`table` 與時間只能取真實結果，沒有資料就顯示尚未確認。

新增獨立的 `cleanup_status`（`not_attempted`、`cleaned`、`failed`、`unknown`），清理僅能處理該操作擁有的測試記錄；不得刪除正式資料。已清理後仍保留操作收據，讓重試不會重寫。缺少讀取或刪除權限時分別顯示已寫入但未驗證、未清理；不能統稱成功且清理乾淨。

以上為擬議的結果契約；實作時同步更新 Go 回覆、TypeScript 型別、服務、UI 與受影響 API 文件。

### 7. 讓輸入與預覽不互相搗亂

每列分開保存草稿、已儲存值與儲存狀態。其他列刷新不得覆蓋目前輸入；同一列的遠端變更必須提示衝突，保留本地文字並提供重新載入或明確重新送出。刪除列後清理其草稿與進行中結果。

Enter 僅走一條提交途徑，中文組字時不送出；連續 Enter、blur 或快速雙擊最多產生一次同內容要求。送出中保留操作身分，不因短暫切換畫面而取消防重複。

預覽／建表回覆必須核對產生時的範圍及版本。過期結果不能更新新設定畫面。忽略舊答案不等於後端已停止操作；沒有取消確認就顯示仍待核對。

唯讀規則涵蓋全部修改動作，包括建表、套用預覽、試寫、連線切換及批量啟停。完成後需明確返回編輯才可修改，修改使相關檢查失效。

### 8. 第 4 步用四個問題引導

1. **資料要存到哪裡？** 顯示設備／方案範圍、資料庫連線、已儲存狀態與測試連線結果。
2. **使用現成資料表，還是建立新的？** 路線明確；「系統安排記錄表」與「自行選表配欄位」不能同時啟用成兩份重複輸出。
3. **哪個資料放哪個欄位？** 使用現成表時顯示來源、目的欄位、檢查、儲存狀態及是否記錄；系統安排記錄表時顯示成員與預期結構，不強迫填手動欄位。詳細位址／型態／分組收在進階區。
4. **現在可以開始了嗎？** 依實際缺項指出下一步；分開顯示設定、建表、試寫、清理、設備運作與最近寫入，未確認不畫成成功。

搜尋與「只看有問題」只影響顯示；批量操作明確標示作用範圍並顯示筆數，不能暗中修改篩選外資料。表格擁有自己的橫向捲動區域，控制項有名稱、焦點可見，錯誤可由鍵盤定位。驗收尺寸訂為 390、768、1440 CSS px；這是設計檢查條件，不是已測量結果。

沿用既有外觀與元件，不引入新的視覺套件。畫面文字進既有 en／zh-TW 翻譯檔，例如「預覽會建立什麼」「哪些資料一起存成一筆」。沒有外部視覺設計來源，不建立虛構設計稿或像素驗收證據。

啟用進度由現有後端實際結果產生，不播放固定步數就宣布完成。部分設備成功、部分失敗要分開呈現；原本已運作的設備不代表這次資料庫修改成功。返回頁面重取真實狀態，不重播假動作。

## Risks / Trade-offs

- 停止假成功可能讓原本看似可用的按鈕變成未開放；這是避免誤導的必要改變，不以成功回覆維持表面相容。
- 真實欄位查詢需要權限且可能較慢；載入／失敗必須可見，不用範例取代。尚未量測速度，不承諾加速比例。
- 不同資料庫的建表還原、時間與試寫語法不同；依已驗證能力開放，未知種類維持封閉，不宣稱全面支援。
- 本地儲存與外部資料庫無法一概保證一起還原；留下可核對操作狀態，接受需要人工確認的結果。
- 任務分組是交付安排，不是工期估算。若實作超出單次可驗證範圍，先更新任務與依賴再拆批，不跳過測試。

## Migration Plan

先加入安全失敗與互動保護，再擴充身分／版本／操作記錄與相容讀取，完成目標與成員移轉後才開放真實操作。新增欄位不得把舊資料自動標為已驗證。每批產品程式變更先寫會失敗的測試，修正後再跑測試與建置。

既有一般建表與 row-group 功能維持相容；若需要改 API，先保留原安全讀取路徑、成套更新呼叫端，再移除過時寫入行為。最後通過完整測試與可丟棄資料庫驗證後才談部署，不能拿正式 PLC／資料庫當測試環境。

回復程式版本不會撤銷已建立的表或已寫入資料；交接需記錄目標版本及實際變更。無法安全核對時停用新的寫入操作，保留設定與證據，不執行破壞性還原。

## Open Questions

沒有需要先由使用者補答才能保存草案的問題。仍需實作前驗證：CLI 正式文件檢查、各目標資料庫實際能力、本地第二段儲存失敗的行為及既有資料相容性。這些是明確的檢查工作，不預先宣稱通過。
